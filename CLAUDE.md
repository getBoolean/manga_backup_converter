# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Manga Backup Converter — a Flutter/Dart monorepo that converts manga backup files between formats: Aidoku (.aib), Paperback (.pas4), Tachi (.tachibk, .proto.gz), Tachimanga (.tmb), and Mangayomi (.backup). Currently a standalone CLI; Flutter app is planned but not yet functional.

## Monorepo Structure (Melos)

- Root: Flutter app + monorepo workspace config (melos scripts, dependency_overrides)
- `packages/manga_backup_core/` — Portable conversion core (KTD14): Aidoku/Paperback/Tachi codecs, normalized data, reconciliation, loss report, builders, migration pipeline, conversion journal; pure Dart, depends only on `source_runtime` contracts (`source_contracts.dart`) — never Flutter, `dart:io`, the CLI, concrete loaders or HTTP (`test/boundary/core_boundary_test.dart` enforces this)
- `packages/mangabackupconverter_cli/` — CLI composition root: commands/TUI, concrete plugin loaders, `lib/src/commands/conversion_composition.dart` (`cliFormatRegistry()` adds the native Tachimanga/Mangayomi codecs and the direct converter; `cliRuntimeRegistry()` registers the Aidoku, Paperback and Tachi desktop runtimes), Tachi→Tachimanga extension; its barrel re-exports `manga_backup_core`
- `packages/aidoku_plugin_loader/` — Aidoku WASM plugin loader (host imports, isolate management, picks runtime)
- `packages/wasm_runner/` — Abstract WASM runner interface (`WasmRunner`, `WasmRuntimeException`, `WasmTrapException`)
- `packages/wasmer_runner/` — Wasmer FFI runner implementing `WasmRunner` (native platforms, build hook downloads prebuilt wasmer)
- `packages/web_wasm_runner/` — Browser WebAssembly runner implementing `WasmRunner` (web platform)
- `packages/wasm3/` — Wasm3 interpreter runner implementing `WasmRunner`
- `packages/quickjs/` — Vendored QuickJS-ng (submodule `vendor/quickjs`, pinned full commit) compiled from source by a `native_toolchain_c` hook with the `src/quickjs_dart.c` wrapper; Dart API `JsRuntime`/`JsContext`/`JsValue`, interrupt token, memory/stack limits, pending jobs (KTD24); nothing is downloaded
- `packages/paperback_plugin_loader/` — Paperback host: per-source QuickJS runtime (`SourceJsRuntime`), promise bridge, resource limits and sizing rule, protocol v1 worker (`bin/paperback_source_worker.dart`); versioned 0.8/0.9 API adapters come in U6 via `PaperbackPackageAdapter`
- `packages/source_loaders/` — The Aidoku/Paperback/Tachi `PluginLoader` adapters over each `SourceProvider` (pure Dart), shared by the CLI and the app composition roots; `AidokuPluginLoader(providerFactory:, client:)`, `PaperbackPluginLoader(worker:)`, `TachiPluginLoader(runtime: TachiLoaderRuntime)`. The CLI re-exports them and keeps `DesktopTachiRuntime` and `desktopPaperbackLoader`
- `packages/app_lints/` — Shared lint rules (based on `solid_lints`)
- `packages/jsoup/` — Jsoup-compatible HTML parsing (Rust scraper on Windows/Linux/Android, SwiftSoup on iOS/macOS, TeaVM on Web)
- `packages/scraper/` — Rust scraper crate (html5ever/Servo) FFI bridge; build hook compiles via cargo + registers CodeAsset; for Android, auto-discovers NDK from `ANDROID_HOME/ndk/` and runs `rustup target add` before cross-compiling
- `packages/swiftsoup/` — SwiftSoup FFI bindings for iOS/macOS; @objc bridge wrapper compiled from Swift via SPM; build hook compiles Swift and registers CodeAsset; Dart bindings generated by ffigen from auto-extracted ObjC header; `SwiftSoupParser` lives in `packages/jsoup/lib/src/swift/` (mirrors scraper pattern)
- `packages/assets/` — Asset code generation
- `packages/constants/` — App-wide constants
- `packages/tachi_plugin_loader/` — Tachi catalogs (`repo.json` → live `index.json`, never `index.min.json`), JAR/APK artifact policy, `TachiRuntime` (`SourceProvider` over the conversion's single JVM worker: `artifact.prepare` with the approved repository fingerprint, package-level loading, unload on last session close), `TachiWorkerLocation` (runtime manifest `tachi-runtime.json` or configured paths); `lib/testing.dart` serves committed captures for tests
- `packages/source_runtime/` — Backend-neutral source contracts, desktop worker protocol v1 (`doc/protocol-v1.md`) and supervisor, `BrowserPort` contract, artifact cache, redactor, capture record/replay (pure Dart)
- `packages/source_runtime_testing/` — Fake `BrowserPort` and reusable source-runtime contract suite (dev dependency only)
- `packages/source_runtime_android/` — Android source runtime: private `:source_runtime` service process for Tachi APK sources, driven from Dart through JNIgen bindings (`ffiPlugin`); no platform channels (KTD23); the app-process WebView `BrowserPort` (`lib/src/browser_port.dart` over the Kotlin `browser/AppBrowserHost` facade, U12) and `AndroidPaperbackBackend` (QuickJS admission; Paperback itself runs through `isolatePaperbackLauncher`); the service hosts the shared Tachi worker (`tools/tachi-source-runner/android`) over Binder stdio (frames > 32 KiB as `SharedMemory`), and `lib/src/tachi_backend.dart` (`AndroidTachiBackend`, `ServiceWorkerProcess`) connects the `source_runtime` supervisor to it; app minSdk is 28 (KTD19)
- `packages/jsoup_jni/` — JNI Jsoup backend (`JsoupParser`, `JreManager`, generated `lib/src/bindings/`); desktop JVM only, retained as a fallback/reference backend
- `packages/source_runtime_ios/` — iOS source runtime: FFI bindings to an embedded interpreter-only JVM (OpenJDK mobile, HotSpot Zero) and WKWebView (U16 gate); backends: local Tachi (`IosTachiBackend`, U9 — the shared Tachi worker in the VM over `InVmWorkerProcess`), `WKWebViewBrowserPort` for the in-app Paperback worker isolate (`isolatePaperbackLauncher` in `paperback_plugin_loader`, U10), Aidoku (`IosAidokuBackend`, U18); build hook links `tools/tachi-source-runner/ios/build/out/<sdk>/lib/libsourcejvm.a` when present; staged runtime payload under `runtime/` is git-ignored; iOS-only, no assets on other OSes
- `tools/tachi-source-runner/` — Desktop Tachi worker (Gradle/JVM, worker protocol v1 on stdio); hosts differ by `PackageRuntime` (how packages are prepared/loaded: `JvmPackageRuntime` with dex2jar for desktop and iOS, `AndroidPackageRuntime`) and `WorkerPlatform` (process identity, platform deadlines, artifact rewrite); `android/` is the Android host module (`:tachi_source_host`, included by the app's Gradle) that compiles the shared sources listed in its `build.gradle.kts` — they must stay free of desktop-only APIs (`ProcessHandle`, dex2jar, the webkit shim) — and loads original APK DEX on ART; `ios/` holds the reproducible OpenJDK mobile Zero build (manifest, scripts, patches, back-edge rewriter, gate fixtures, privacy manifest; outputs in git-ignored `build/`)

**Tests never contact a server.** HTTP in tests goes through capture replay (`fromAix(httpClient:)` for Aidoku); captures live under `fixtures/source_captures/<ecosystem>/<source>/` and are refreshed only by `tool/capture_source_fixtures.dart` (never hand-edited; nested `.gitattributes` keeps them byte-exact). Captures keep only `content-type`, `location`, `retry-after` response headers.

## Architecture

**Riverpod App Architecture** — feature-first with layered structure per feature:

```txt
lib/src/features/<feature>/
  ├── domain/         # Entities, value objects (freezed + modddels)
  ├── data/           # Repositories, DTOs (dart_mappable), data sources
  ├── application/    # Riverpod providers/controllers (riverpod_generator)
  └── presentation/   # ConsumerWidgets, screens
```

Active features: `books`, `connectivity`, `conversion`, `initialization`, `settings`.

`lib/src/features/conversion/application/conversion_composition.dart` is the app's runtime composition root: `IosSourceRuntimes.start(IosConversionConfig)` registers Aidoku (`IosAidokuBackend`), Paperback (worker isolate, KTD25 plan measured on device) and Tachi (embedded JVM via the common `TachiRuntime`, `hostCompatibility: iosTachiHostCompatibility`) sharing one `WKWebViewBrowserPort`; per-conversion scopes are adopted by the job's `ConversionOwner` (`ConversionService(onOwnerOpened:)`). Tachi limits are explicit app config (no iOS sizing rule). `iosConversionServiceOverride` installs it for Riverpod; nothing starts at app launch. App-local output/journal: `conversion/data/app_file_stores.dart`. iOS integration suites: `source_runners_ios_test.dart` (U15 conversions; harness in `integration_test/support/`), `_tachi_test` (U9), `_paperback_browser_test` (U10), `_aidoku_test` (U18); `scripts/ios_package_check.sh` records slices/hashes and enforces the R18 checks The `example_feature` directory is a reference template showing the full pattern.

### CLI Package Architecture

`packages/mangabackupconverter_cli/` is organized by format:

- Portable code lives in `packages/manga_backup_core/` (KTD14): `lib/src/common/` (`ConvertableBackup`, mappers), `lib/src/formats/{aidoku,paperback,tachi}/` (codecs; Tachi protobuf under `formats/tachi/proto/`), `lib/src/conversion/` (BackupFormat, normalized data, `MigrationPipeline`, `SelectionPort`, `ConversionReport`, `ConversionJournal`, builders, rating policy, trust gate), `lib/src/reconciliation/` (reconciler + `ChapterDecision`). The CLI barrel re-exports it
- `lib/src/converter.dart` — `MangaBackupConverter` class with import methods per format
- `lib/src/formats/{tachimanga,mangayomi}/` — native-dependent legacy codecs kept outside the core; `tachi_to_tachimanga.dart` holds the `TachiToTachimanga` extension and `legacyDirectConvert` (the pipeline's injected `DirectConverter`)
- `lib/src/pipeline/plugin_loader.dart` — concrete loaders (`AidokuPluginLoader` over `AidokuSourceProvider` + `SessionPluginSource`, `StubPluginLoader`s, `UnavailableTachiPluginLoader`); `cliRuntimeRegistry()` in `commands/conversion_composition.dart` is the only format→loader map (`pluginLoaderFor` was removed); `BackupFormat` no longer constructs loaders (KTD15)
- `lib/src/commands/` — CLI command implementations + interactive terminal UI (`terminal_ui.dart`, `migration_dashboard.dart`, `live_search_select.dart`, `manga_details_screen.dart`, `extension_select_screen.dart`)
- CLI TUI screens use `TerminalContext` + `ScreenRegion` for all I/O, NOT `print()` — `print()` goes through Dart zones while `TerminalContext.write` does not, enabling zone-based log redirection in interactive mode
- `TerminalContext` bundles KeyInput, ScreenRegion output, SIGINT handling, and terminal dimensions — screens receive it as a parameter, never create their own I/O objects
- `ScreenRegion.render` calls `writeln` for every line — NEVER pad output to `context.height` lines; the final `writeln` scrolls the terminal past the bottom, corrupting the TUI; let `clearDown()` handle leftover space (no other TUI screen pads)
- TUI scroll indicators ("↑ more above" / "↓ more below") consume lines from the viewport budget — subtract them from the line budget BEFORE packing entries, or the output overflows the terminal
- Variable-height TUI entries (e.g. wrapped detail lines): compute `maxVisible` by packing entries into a line budget from `scrollOffset`, not by dividing available lines by a fixed entry height
- `TerminalContext` is single-use per process — `dispose()` cancels `_stdinSub` (broadcast source), permanently killing stdin and preventing event loop hangs; use one context for the entire interactive session
- `readLineSync()` must be called BEFORE creating `TerminalContext` — once the context puts stdin in raw mode (`lineMode=false`), `readLineSync()` won't work; use `_readYesNo` for y/N prompts and `_readLine` (in `convert_command.dart`) for free-text input after context creation — both read raw keys from `KeyInput`
- Raw mode output: when `TerminalContext` is active, use `\r\n` (not `\n`) for newlines in `context.write()` calls — raw mode disables automatic CR insertion
- `TerminalContext.test()` constructor accepts `StringSink` + `Stream<List<int>>` for testable rendering/input
- `MangaDetailsScreen.run()` returns `Future<bool>` — `true` = Enter (confirm selection), `false` = Escape (go back); `LiveSearchSelect` closes the event loop on `true` (same as direct Enter on a result)
- `ExtensionSelectScreen` Enter behavior: `when cursorIndex >= 0` guard — Enter does nothing while search bar is focused; with extensions toggled returns toggled set, without toggled auto-selects highlighted entry
- CLI TUI hyperlinks: wrap text in `green()` then `hyperlink()` — `green(text)` not `green(bold(text))` to match the dashboard's color; bold brightens green to a different shade
- `renderMarkdown()` in `terminal_ui.dart` converts markdown (`[text](url)`, `**bold**`, `*italic*`) to ANSI escapes — applied per-line AFTER `wordWrap()` to avoid ANSI sequences spanning wrapped lines
- `win_console_stub.dart` / `win_console_native.dart` — conditional import (`dart.library.ffi`) enables `ENABLE_VIRTUAL_TERMINAL_INPUT` on Windows; `enableVirtualTerminalInput()` called in `KeyInput.start()`, `restoreConsoleMode()` in `dispose()`
- `SearchInputState` in `terminal_ui.dart` owns query text, cursor position, focus state (`focused`), key routing (`tryHandleKey` → `SearchKeyResult`), and box rendering (`renderBox`) — callers pass unhandled keys through and check the result enum; `renderSearchInput()` renders the ANSI inverse block cursor
- Both search screens use `cursorIndex` (`-1` = search bar, `>= 0` = result) and sync `searchInput.focused` on arrow navigation; `tryHandleKey` auto-refocuses on text-modifying keys (CharKey, Backspace, Delete) but leaves Space to callers for screen-specific actions
- `KeyInput` parses two escape sequence formats: `ESC [ <byte>` (arrows, Home, End) and `ESC [ <digit> ~` (Delete=3); the escape buffer handles split delivery across both
- `KeyInput` enables SGR extended mouse mode (`\x1b[?1000h\x1b[?1006h`) on `start()` and disables on `dispose()` — scroll wheel events parsed as `ScrollUp` (button 64) / `ScrollDown` (button 65); all other mouse events silently discarded
- TUI screens with a search bar (`cursorIndex = -1`) must reset `scrollOffset` to `0` when cursor enters the search bar — otherwise viewport stays scrolled, showing stale "↑ more above" indicator
- `KeyInput._controller` is broadcast — parent screens `cancel()` their subscription before opening a child screen, child creates its own subscription, then parent creates a fresh subscription on return (declare `keySub` as non-final). Do NOT use `pause()`/`resume()` (causes buffered event flood) or `suspend()`/`start()` (removed)
- `convert_command.dart` builds a `CallbackSelectionPort`; interactive callbacks run inside `paused(...)` (`spinner.stop()` → `loadingRegion.clear()` → `context.showCursor()` → TUI screen → `context.hideCursor()` → `spinner.start(...)`). Non-interactive mode uses auto-select fallbacks (exact-title-only for match confirmation; see `autoAcceptMatches`), resolves no chapters, rejects first-seen repository fingerprints, and accepts a partial conversion only with `--accept-partial` (otherwise `PartialConversionDeclined`: nothing written, exit 1)
- CLI adult-source policy: `SourceRatingPolicy` (core) hides NSFW and unknown ratings until `--confirm-adult`; `--max-rating nsfw` without it is a `UsageException`; the policy runs before `--extensions` matching and auto-select
- CLI log: one `Redactor` (`source_runtime`) behind `RedactingLog`; every zone `print`, stderr error, progress message and failure message entering the report/journal is redacted; loaders report each source's `SettingsSnapshot` via `onSettings` so its secrets are registered
- CLI output is written with `writeFileAtomically` (temp sibling + rename); the conversion journal (`--journal`, default `<output>.journal.json`, `FileJournalStore`) is deleted after publication; remembered repository fingerprints live in `userConfigDirectory()/trusted_repositories.json` (`FileTrustStore`), never the temp dir
- `convert_command.dart` uses `runZoned` with `ZoneSpecification.print` to redirect all `print()` (including from `aidoku_plugin_loader`) to a log file when interactive; `Zone.root.print()` escapes the zone for user-facing messages
- `_readPath` in `convert_command.dart` hides the terminal cursor on entry (`_renderPathInput` draws its own inverse-video block cursor) and restores it on all exit paths — callers should not call `showCursor()` before `_readPath`
- `PathInputState.handleKey()` exhaustively matches all `KeyEvent` subtypes — no `default` case needed; adding new `KeyEvent` subtypes requires adding a case here
- `extension_entry.dart` — `ExtensionEntry` sealed class (`id`, `name`, `languages`, `contentRating` (0=Safe, 1=Suggestive, 2=NSFW), `cacheKey`); `AidokuExtensionEntry` adds `version`, `altNames`, `iconUrl`, `downloadUrl`, `baseUrl?` (`cacheKey` = `'$id-v$version'`); `StubExtensionEntry` has only base fields (`cacheKey` = `id`)
- `PluginLoader` (core) has `downloadPluginBytes(entry)` and `loadPluginFromBytes(entry, bytes, {owner})` (returns `SourceOutcome<PluginSource>?`; null = unsupported) — `AidokuPluginLoader` overrides both; `CachingPluginLoader` uses these to cache/restore plugin bytes format-agnostically. `loadPlugins` takes `owner` (adopt each plugin as soon as it opens) and `onFailure` (typed `PluginLoadFailure`); `fetchExtensionLists` takes `trust` (`RepositoryTrustGate`) for signed repositories
- `lib/src/pipeline/plugin_source_stub.dart` — `StubPluginSource` implements `PluginSource` with typed `CapabilityUnavailableFailure`s; must be updated when the interface changes
- `SourceMangaData` (core `conversion/source_manga_data.dart`) — normalized type (chapters, history, tracking, categories); `ConvertableBackup.extractionLosses` reports records a codec could not extract (Paperback dangling library entries)
- `TargetBackupBuilder` (core, abstract) — `format`, `build(List<MangaConversionPlan>, {sourceFormatAlias, report})` and `validate(bytes, plans)`; writers consume `planConversion` results and never rematch. Writers: `AidokuBackupBuilder`, `PaperbackBackupBuilder` (`lib/src/writers/`; `.pas4` V4 graph, generated backup-local IDs via `paperbackLocalId` kept apart from runtime `sourceId`/`mangaId`/`chapterId`), `TachiBackupBuilder` (Mihon only; `source` = exact runtime int64 ID, `url` = `SManga.url`, chapter `url` = the Tachi runtime's `chapterId` (`SChapter.url`), raw scanlator/chapter number from `PluginChapter.context`). Shared accounting helper: `accountChapterState`; validators use `FetchedChapterIndex`. Tracking is written only for Mihon→Mihon (same tracker registry); everywhere else it is reported unrepresentable
- **Postcard integer encoding**: `u8`–`u64` → unsigned varint (LEB128); `i8`–`i64` → zigzag varint; `f32` → 4 LE bytes; `f64` → 8 LE bytes. Both `PostcardReader.readI64` and `PostcardWriter.writeI64` use zigzag varint, NOT raw bytes
- **Postcard zigzag web safety**: JS bitwise ops work on 32-bit signed ints — use arithmetic (`isOdd`, `~/ 2`, `* 2`) not bitwise; see `postcard_reader.dart`/`postcard_writer.dart`
- **Wasm3 code assets**: `packages/wasm3/hook/build.dart` compiles vendored wasm3 C source via `native_toolchain_c` and registers it as a `CodeAsset` with `DynamicLoadingBundled()` — runs automatically during `dart run`, `dart build`, `dart test`; no manual install needed; defines `M3_HAS_TAIL_CALL=0` for Android armv7 — NDK clang 18 crashes on `musttail` attribute
- **Wasm3 version**: vendored at latest HEAD (`79d412e`, post-v0.5.0); `m3_emit.c`, `m3_emit.h`, `m3_optimize.c` were removed upstream (merged into `m3_compile.c`) — `hook/build.dart` reflects this; regenerate bindings with `dart run ffigen --config ffigen.yaml` from `packages/wasm3/`
- ffigen config in `packages/wasm3/ffigen.yaml`; uses `ffi-native` mode — generates `@Native`-annotated top-level functions
- `Wasm3Runner` `readMemory`/`writeMemory`/`call` throw `WasmRuntimeException` (an `Exception`, not `Error`)
- `WebWasmRunner.call` throws `WasmRuntimeException` for missing exports — NOT `ArgumentError`
- `MangaConverterException`, `WasmRuntimeException`, `WasmTrapException`, `AixParseException`, `SourceListFetchException` all have optional `cause` and `stackTrace` fields — use `Error.throwWithStackTrace` when re-wrapping exceptions to preserve the original stack trace
- **WASM runner conditional export**: `aidoku_plugin_loader/lib/src/wasm/wasm_runner.dart` re-exports `wasm3` on native, `web_wasm_runner` on web via `if (dart.library.js_interop)`
- Root `pubspec.yaml` must depend on packages with build hooks (wasm3, scraper, swiftsoup, quickjs — all path dependencies) for `dart test` from root to discover code assets
- **No `print()` in WASM isolate code** — `aidoku_host.dart`, `wasm_isolate.dart`, and the active WASM runner route all log messages through `onLog` callback (threaded via `buildAidokuHostImports` and `WasmRunner.fromBytes`), which sends `WasmLogMsg` to the main isolate; this allows `convert_command.dart`'s `runZoned` print redirect to capture them
- `_processCmd` in `wasm_isolate.dart` replies via `cmd.replyPort.send()` — when changing reply format (e.g. to a tuple), update ALL corresponding `await port.first as ...` casts in `aidoku_plugin_io.dart`
- **Isolate error handling**: `wasmIsolateMain` and `_processCmd` use `on Object catch` (not `on Exception catch`) — `Error` subtypes (`ArgumentError`, `RangeError`, `StateError`) from the WASM runner/FFI must be caught or the isolate dies silently, causing `port.first` hangs on the main isolate
- **WasmSemaphore platform backends**: Windows → `CreateSemaphoreA` (kernel32); macOS/iOS → GCD `dispatch_semaphore_*` (libSystem via `DynamicLibrary.process()`); Linux/Android → POSIX `sem_init`/`sem_wait`/`sem_post` — `sem_init` is deprecated and non-functional on macOS (returns -1, ENOSYS), so POSIX must NOT be used on Apple platforms
- **Isolate init failure**: Runner creation happens AFTER the handshake sends cmdPort — if `WasmRunner.fromBytes` fails, the isolate enters a command-drain loop replying with errors (can't send on the already-consumed handshake port)
- **`_sendErrorReply` in `wasm_isolate.dart`**: Best-effort error reply for all command types; `WasmSearchCmd`/`WasmMangaDetailsCmd` reply with `(String error, List<String>)`, all others reply with `null`
- `aidoku_plugin_io.dart` (native) and `aidoku_plugin_web.dart` (web) are conditional exports of `aidoku_plugin.dart` — any public method added to one MUST be added to the other
- Host import errors (CSS selector failures, HTML parse errors) are logged with `[CB]` prefix via `onLog` — `wasm_isolate.dart` accumulates these during WASM calls and returns them as warnings alongside results; `PluginSearchPageResult.warnings` carries them to the pipeline; `_streamSearch` emits `PluginSearchError` for non-empty warnings; web worker `console.warn` calls in `wasm_worker_js.dart` must also use `[CB]` prefix for consistency
- WASM plugins are single-threaded — `AidokuSourceSession` serializes calls per source; the migration dashboard serializes searches (one manga at a time); `_streamSearch` emits raw search results and typed `PluginSearchError`s only — the pipeline fetches each confirmed match's snapshot with `fetchDetails(ref)` (concurrently across manga) after confirmation, reusing journaled snapshots
- `migration_dashboard.dart` search lifecycle: `activeEntry` tracks the entry being searched; `pendingRetries` queues re-selected entries; `startNextSearch` drains retries before the linear index scan — the scan skips deselected entries AND entries that already have a `match` (a manual choice made before the queued search ran — `startSearch` clears `match`, so searching would discard it), setting `searching = false`; re-select logic must check `match == null` (not `searching`) to decide whether to retrigger
- `migration_dashboard.dart` auto-match (R8): takes only first result per plugin, enriches all candidates via `onFetchDetails` on `_SearchDoneEvent`; `_EnrichmentDoneEvent` carries enriched results back to the event loop, which sets `match = uniqueExactTitleMatch(title, candidates)` — confirmed automatically ONLY when exactly one candidate across all plugins has the exact title (case-insensitive, whitespace-collapsed); otherwise `match` stays null and the entry waits for the user to choose. Chapter count is NOT used to pick a match (`_findBestMatch` no longer exists)
- `autoAcceptMatches` (non-interactive fallback in `convert_command.dart`) also uses `uniqueExactTitleMatch` — it does NOT fall back to the first result; unmatched manga stay unresolved and are listed in the conversion summary (`pipeline/conversion_summary.dart`)
- `migration_dashboard.dart` Tab key: opens `MangaDetailsScreen` for the highlighted entry's match (view-only); does NOT cancel `activeSub` — non-destructive unlike Enter which needs exclusive plugin access; reuses enriched `details`/`chapters` when available
- `diceCoefficient` in `terminal_ui.dart` — bigram Dice coefficient (0.0–1.0) for title similarity; used by live search sorting
- `live_search_select.dart` display rows include non-selectable group headers (result index `-1`); scroll offset operates in display-row space, not result-index space
- `get_manga_update` WASM ABI: `(manga_descriptor_rid, needs_details, needs_chapters)` — `getMangaDetails` accepts `{bool includeChapters = false}`; `AidokuSourceSession.fetchManga` passes `includeChapters: true` so chapters are included in migration output
- `PluginSearchResult` carries the source's durable `NativeMangaRef ref` (`pluginSourceId`/`mangaKey` are getters on it), optional `pluginSourceName`, `details` and `chapters` — NOT populated during search; enrich with `enrichedWith(FetchedManga)` (preserves `pluginSourceName`, keeps `fetched`; dashboard/live-search Tab reuse `fetchedOutcome` before fetching). `onFetchDetails`/`FetchDetails` take the ref and return `DetailsOutcome` (`DetailsFetched` / `DetailsEmpty` / `DetailsFailed`); a failed fetch leaves the manga unresolved in the report, never built with no chapters
- `PluginChapter.scanlators` keeps every group; `scanlator` joins them (Aidoku's single field; the builder adds a report note)
- Search failures travel on `MangaMatchConfirmation.searchFailures` from the dashboard (`entry.failures`, also fed by live search `onFailure`) and `autoAcceptMatches` into `ConversionReport.failures`; dashboard deselection is `excluded: true` (an explicit exclusion, not a loss)
- WASM `get_search_manga_list` returns minimal data (authors typically empty); full author/artist data comes from the details fetch (after confirmation, not during search) — always prefer detail-level fields over search-level fields when both exist
- `PluginMangaDetails` has separate `authors` and `artists` lists — display code should merge both into a `<String>{}` set to deduplicate (authors who are also artists)
- Generated Tachi fork protobuf code (mihon, j2k, neko, sy, yokai) lives in `packages/manga_backup_core/lib/src/formats/tachi/proto/`; `.github/workflows/update-schemas.yml` regenerates it there (`OUTPUT_DIR_PREFIX`), and no copy remains in the CLI
- Exceptions: core `lib/src/exceptions/` (base, aidoku, paperback, tachi, migration, plus `PartialConversionDeclined` in the pipeline); CLI keeps tachimanga and mangayomi

Each backup format class has a `fromData(Uint8List)` factory and conversion methods to other formats.

## Pipeline & Backup Format

- `BackupFormat` (sealed) is the single type for all format selection (CLI, pipeline, TachiBackup)
- Aliases: `aidoku, paperback, mihon, sy, j2k, yokai, neko, tachimanga, mangayomi`
- `BackupType` enum and `TachiFork` enum have been deleted — do not recreate
- `TachiBackup.format` is `Tachiyomi` (sealed subtype of `BackupFormat`), not an enum
- `Mangayomi` extends `BackupFormat` directly, not `Tachiyomi`
- `BackupFormat` hierarchy uses dart_mappable `discriminatorKey`/`discriminatorValue` for serialization
- `TachiUpdateStrategy` uses `ValuesMode.indexed` — maps to/from `int` (0=alwaysUpdate, 1=onlyFetchOnce), not string names
- `ConversionStrategy` (sealed): `DirectConversion` (Tachimanga↔Tachi) or `Migration` (all other pairs including same-format); no `Skip` — all pairs allow plugin migration
- `MigrationPipeline.run()` accepts `forceMigration` — when true, `DirectConversion` pairs use plugin migration instead of direct conversion
- KTD15: `BackupFormat` carries identity only (no `backupBuilder`, no loader). `FormatRegistry` (core) holds codecs (`BackupDecoder`), writers and the `DirectConverter` (`(source, target, report)`); `FormatRegistry.portable()` = Aidoku/Paperback/all Tachi fork codecs + Aidoku/Paperback/Mihon writers. `RuntimeRegistry` (core, injected) holds `DestinationRuntime`s (`ecosystem`, `serves`, `createLoader`, cheap `probe` — never starts a worker). `conversionUnavailable(formats, runtimes, source, target)` decides enablement per pair
- `ConversionJob` (core) is the one job every host runs: decode via codec → enablement check → `MigrationPipeline` → publish `draft.bytes` through the injected `ConversionOutput` (atomic) → clear journal. The CLI (`convert_command.dart`) and the Flutter `ConversionService` (`lib/src/features/conversion/application/`) differ only in injected adapters
- KTD8 pre-publish validation: the pipeline serializes once (`ConversionDraft.bytes`), runs `writer.validate(bytes, plans)` before asking for partial acceptance, and throws `InvalidConversionOutput` (nothing published); direct conversions are re-decoded by the target codec. A destination with no writer/runtime is `DestinationUnavailable`
- **User-supplied only**: product code never provides or references an extension or repository. Repositories come from the user (`--repos`, prompted interactively; required unattended; app: `ConversionRequest.repoUrls`), extensions are picked by the user (selection screen, or `--extensions`/`--sources`; unattended runs without them are a usage error — never auto-picked), and settings come from the user (`--settings file.json`, `--setting EXTENSION_ID=KEY=VALUE`; app: an injected `ExtensionSettingsProvider`). `UserExtensionSettings` (core) parses `{"extensions": {"<id>": {"values", "secrets", "sources": {"<sourceId>": {...}}}}}` into `SettingsSnapshot`s; loaders receive them through `RuntimeContext.settingsFor` (`DestinationRuntime.createLoader(context)`); Aidoku merges the repository base URL default under the user's values (`withDefaults`). Pinned repositories/artifacts under `fixtures/` and test fixture dirs are test-only
- `SourceLanguagePolicy`: language narrowing applies only inside the extensions the user picked — each picked package keeps its sources in the backup's languages (chapter languages + Aidoku-style `<lang>.<name>` source IDs) plus `all`/`multi` ones (`PluginSource.language`, e.g. Tachi MangaDex's per-language sources); a picked package with no matching source keeps all its sources; the selection list is never filtered by language. A backup with no recorded language (Tachi) narrows nothing; `--languages en,ja|all` overrides; `--sources` (exact runtime source IDs) skips narrowing and every named source must load
- Direct conversion is registered only for verified targets (`registerDirectConverter(..., targets: [Tachimanga, Mihon])`); other Tachi forks are not output formats
- Reconciler (KTD7 refinements, U7): a chapter language that is not a language code (Paperback bundles report flag emoji such as `🇬🇧`) is unknown, never a conflict; when the source chapter has a number but no destination chapter has that number, a unique exact title among destination chapters without numbers can match (Tachi WeebCentral returns titles like "Step 1" and no numbers). Ties stay ambiguous
- `TachiBackup.toData()` encodes Mihon field by field (`encodeMihonBackup`, exact `Int64`s); the other forks still use the untested generated-JSON path and have no registered writer
- `TachiBackup.toTachimangaBackup()` flattens nested Tachi structures into normalized Tachimanga DB tables with autoincrement-style sequential PKs (matching Tachimanga's `IntIdTable`); history is collapsed to one row per manga (Tachimanga's History table has `UNIQUE(manga_id)`) — latest chapter by `lastRead` timestamp, summed `readDuration`; Source IDs are preserved as-is (Source table uses `BIGINT NOT NULL`, not autoincrement)
- `TachimangaBackupDb.exportDatabase` writes to a fresh scratch database per export (never the shared `tachimanga.db` file), lets SQLite create `sqlite_sequence` itself, and stores booleans as 0/1; `TachimangaBackup.fromData` treats `pref.json`/`pref-all.json` as optional (converted backups carry library data only). The direct path's report notes how many history rows were folded

### Pipeline Data Flow

- `MigrationPipeline` (core) takes a `SelectionPort` (`selectSources`, `decideRepositoryTrust`, `confirmMatches`, `resolveChapters`, `acceptPartialConversion`); `CallbackSelectionPort` adapts callbacks with conservative defaults (reject trust, resolve nothing, decline partial unless `acceptPartial`). `confirmMatches` is a batch callback receiving the manga still needing a decision plus `onSearch` and `onFetchDetails`
- `MigrationPipeline.run()` returns a `ConversionDraft` (`backup`, validated `bytes`, complete `ConversionReport`, `plans`, `partialAccepted`); it creates a `ConversionOwner` before fetching lists/loading (`onOwnerOpened` lets composition roots adopt runtime scopes) and awaits `owner.close()` in `finally`
- Conversion journal: pass `journalStore` + `run(inputIdentity:)`; stable keys come from `stableMangaKeys`/`stableChapterKey`. Only decisions are journaled (matched with ref, search-level fields and snapshot; excluded) — unmatched manga are searched again on resume; sources are always re-selected; matches whose source identity (artifact digest) or settings revision changed are reopened; journaled snapshots are reused (no re-fetch); a journaled partial acceptance is reused only for an identical `report.digest`; never journal secrets. CLI: `onResume` prints a notice, `--fresh` discards the journal
- `PluginSearchEvent` (sealed) streams search results per-plugin: `PluginSearchStarted` (with optional `pluginName`) / `PluginSearchResults` (with optional `pluginName`) / `PluginSearchError`
- `MangaMatchConfirmation.sourceManga` is `SourceMangaData` (not `MangaSearchDetails`) — carries chapters, history, tracking, categories from source backup
- `ConvertableBackup.sourceMangaDataEntries` extracts `List<SourceMangaData>` from each backup format
- `MangaMatchProposal.sourceManga` remains `MangaSearchDetails` (UI display only)
- `MangaSearchDetails` constructor applies `fixDoubleEncoding` (from `common/fix_double_encoding.dart`) to all text fields (`title`, `altTitles`, `authors`, `artists`, `description`) — NOT a const constructor; do not use `const MangaSearchDetails(...)`
- `SourceChapter`, `SourceHistoryEntry`, `SourceTrackingEntry`, `PluginChapter` constructors apply `normalizeChapterNumber` (from `common/normalize_chapter_number.dart`) to chapter/volume numbers — NOT const constructors
- `tachi_backup.dart` must directly import `tachi_backup_chapter.dart`, `tachi_backup_history.dart`, `tachi_backup_tracking.dart` — they are NOT re-exported by `tachi_backup_manga.dart`

## Other Instructions

- WASM_ABI.md in aidoku_plugin_loader documents the Aidoku ABI; cross-check against aidoku-rs source if behavior doesn't match
- IMPORTANT: Compiled .aix plugins may use older aidoku-rs versions — always verify enum/struct layouts against integration tests with real plugins, not just aidoku-rs source
- `AidokuPlugin.fromAix()` accepts `defaults: Map<String,dynamic>` to pre-seed per-source defaults (e.g. auth tokens); keys are raw (no sourceId prefix); values are postcard-encoded to `Uint8List` (bool→`writeBool`, int→`writeSignedVarInt`, String→`writeString`); see WASM_ABI.md "defaults" section
- `HostStore.defaults` stores ONLY `Uint8List` values (postcard-encoded) — no raw `int` or `String`; `defaults::get` adds as `BytesResource` and returns RID; `defaults::set` reads `[u32 len LE][u32 cap LE][data]` from WASM memory (same layout as `send_partial_result`)

- `HostStore` is shared between web (Worker) and native (WASM isolate) — stores raw `Uint8List` resources

The memory limit is enforced in the wrapper's allocator (`memoryLimitHit` is authoritative: on OOM the engine may throw `null`, which inside a promise job looks like `reject(null)`); interrupt reasons are sticky until `clearInterrupt()`

- **SwiftSoup Swift toolchain**: the hook runs `xcrun --sdk <sdk> --find swift`, not bare `swift` — a swiftly (or other) toolchain first on PATH lacks the iOS Swift runtime/SDK overlays and breaks iOS builds; don't "simplify" back to `swift`
- **`flutter build ios` migrations**: Flutter re-applies its Swift Package Manager and UIScene Runner migrations to `ios/` on every build — do not commit those migration changes; revert them (`git checkout -- ios/`) before committing
- **Windows build hook DLL race**: `PathExistsException` when `dart test` tries to copy native DLLs that already exist in `<package>/.dart_tool/lib/`; fix: `rm -rf <package>/.dart_tool/lib/` and retry
- **jsoup platform routing**: Windows/Linux → Rust scraper (`ScraperParser`); Android → Rust scraper; iOS/macOS → SwiftSoup (`SwiftSoupParser`); Web → TeaVM (`TeaVMParser`); `parser_native.dart` returns `SwiftSoupParser()` for iOS/macOS, `ScraperParser()` for all others
- **SwiftSoup backend** (`packages/swiftsoup/`): SwiftSoup 2.7+ compiled to dynamic library via SPM; `SwiftSoupBridge` @objc class in `swift/Sources/SwiftSoupWrapper.swift` wraps SwiftSoup API with handle-based stores (elements, node lists, text nodes); ObjC header generated by SPM build at `.build/.../SwiftSoupWrapper-Swift.h`, minimal header in `swift/SwiftSoupBridge.h`; ffigen generates Dart bindings from the minimal header; `hook/build.dart` compiles Swift for macOS/iOS and registers as CodeAsset
- **SwiftSoup binding regeneration**: `cd packages/swiftsoup && dart run tool/generate_bindings.dart` — builds SPM, auto-extracts `SwiftSoupBridge.h` from SPM-generated `SwiftSoupWrapper-Swift.h` (strips Swift macros), then runs ffigen; header is auto-generated, not manually maintained
- **SwiftSoup dylib preload**: `swiftsoup_init()` (`@_cdecl` in Swift, `@ffi.Native` in Dart) must be called before any ObjC class access — ffigen ObjC bindings use `objc.getClass()` (`late final`) which resolves before `@ffi.Native` functions trigger `@DefaultAsset` dylib loading; `SwiftSoupParser` constructor calls `_ensureLoaded()` to force this; `generate_bindings.dart` extracts plain C function declarations from the SPM header alongside the `@interface` block
- **JAR discovery**: `JreManager._findJsoupJar()` checks exe-relative paths → walks upward from `Directory.current` for `.dart_tool/hooks_runner/shared/jsoup/build/jsoup-<version>/`; no env var fallbacks; version constant in `lib/src/jsoup_version.dart`
- **MSYS2/MinGW CMake**: Windows backslash paths cause `Invalid character escape` in CMake; use `/c/...` format (not `C:\...`); `jni:setup` expects MSVC `Debug/` layout — `generate_jni_bindings.dart --jni-setup` works around this by rescuing `libdartjni.so` from the temp dir
- **JNI test prereq**: Run `melos run jni_setup` (or `dart run tool/generate_jni_bindings.dart --jni-setup` from `packages/jsoup_jni/`) — uses bundled JDK and handles MSYS2/MinGW CMake path issues; raw `dart run jni:setup` fails under MSYS2
- **jsoup tests**: `@TestOn('vm')` required (native-only); create fresh `Jsoup()` in `setUp`, call `jsoup.dispose()` in `tearDown`; scraper backend is default on Windows/Linux — no JRE/JNI setup needed; JNI backend tests tagged `@Tags(['jni'])` and skipped by default via `dart_test.yaml` — run separately: `dart test -t jni --run-skipped` (avoids Windows VEH crash when combined with scraper tests)
- **jsoup_jni JNI tests: one file per run** — e.g. `dart test --reporter expanded -t jni --run-skipped test/jni_contains_test.dart` from `packages/jsoup_jni/`; running the files together fails `jni_contains_test` because `JreManager.ensureInitialized()` returns early once `jvm.dll` is loaded and skips its JAR/library-path setup for later files
- **Windows DLL loading**: `dartjni.dll` depends on `jvm.dll` at load time; `JreManager` pre-loads `jvm.dll` by full path (`DynamicLibrary.open(jvmLibPath)`) before `Jni.spawnIfNotExists` — no PATH modification needed
- **JVM is process-global**: Use `Jni.spawnIfNotExists` (not `Jni.spawn`) — child isolates share the JVM created by the main isolate; `JreManager.ensureInitialized()` is safe in child isolates (early return via `GetModuleHandleW` when jvm.dll already loaded)
- **Web backend** (TeaVM): `TeaVMParser` in `lib/src/web/teavm_parser.dart` — loads TeaVM-compiled Java Jsoup via Blob URL + `importScripts` (Worker-only); the UMD module exports all bridge functions on `self`
- `platform/parser_web.dart` is the web branch of the conditional export — MUST NOT import files that use `dart:io` or `dart:ffi` (transitive imports included)
- `host_store.dart`: `HtmlElementResource`, `HtmlElementsResource`, `BytesResource`, `HttpRequestResource`, canvas/image/font resources
- **Response headers**: `HttpRequestResource.responseHeaders` populated by `net::send` — native path: JSON-serialized through `WasmSharedState` header slots (`headersPtrSlot`/`headersLenSlot`); web path: parsed from `XMLHttpRequest.getAllResponseHeaders()`; `AsyncHttpDispatch` typedef returns `({int statusCode, Uint8List? body, Map<String, String> headers})`
- **Web JS interop**: `dart:js_interop_unsafe` is required for `JSObject.getProperty`/`setProperty`; `JSNull`/`JSUndefined` are not types — use `jsValue.isUndefinedOrNull` instead; extension types with setters need matching getters (`avoid_setters_without_getters`)
- **Aidoku web WASM**: Runs in a Dart isolate (`lib/src/web/wasm_worker_isolate.dart`) compiled to a Web Worker
  - Reuses `buildAidokuHostImports()`, `HostStore`, `WasmRunner` (web), `Jsoup()` (TeaVMParser) — unified with native
  - `Isolate.spawn(wasmWorkerMain, initMap)` + `SendPort`/`ReceivePort` with Map-based messages (structured-cloneable)
  - Sync XHR via `dart:js_interop` (`_JSXMLHttpRequest`) — required because WASM host imports must return synchronously
  - `LazyWasmRunner` (`lib/src/wasm/lazy_wasm_runner.dart`) breaks circular dependency — shared by both native `wasm_isolate.dart` and web `wasm_worker_isolate.dart`
  - Rate limiting enforced in-worker via `RateLimiter` + busy-wait before each sync XHR (unlike native where it's on the main isolate, because web HTTP is synchronous)
- **Web JS interop arity**: dart2js `.toJS` creates fixed-arity JS functions; WASM imports need variable-arity. `_varArgsFactory` in `packages/web_wasm_runner/lib/src/web_wasm_runner.dart` uses `eval` to create wrappers that forward `arguments` as JSArray to a 1-arg Dart bridge. Requires `eval` (already needed since WASM uses `wasm-eval`)
- **TeaVM web bundle** (`packages/jsoup/`): `tool/build_teavm.dart` compiles `tool/teavm/` (Maven + TeaVM 0.13.0 + Jsoup 1.23.2) → `lib/src/web/teavm_bundle.dart` (719 KB minified JS as const string); `package:jsoup/teavm.dart` exports `teavmJsoupJs`
- **TeaVM build requirements**: JDK 17+ and Maven 3.x; `pom.xml` needs explicit `teavm-core` dep (contains `PlatformDetector`); uses `@JSExport` (not `@Export`); ADVANCED optimization < FULL size
- **TeaVM Java bridge** (`tool/teavm/src/main/java/.../JsoupBridge.java`): 54 `@JSExport` static methods wrapping Jsoup API with `HashMap<Integer, Object>` handle store; method renames: `id`→`elementId`, `get`→`getAt`, `remove`→`removeElement`, `dispose`→`disposeAll` (mapped back in `TeaVMParser`)
- **`code_assets` `OS` class**: No `web` constant — only native OS values (android, iOS, linux, macOS, windows, fuchsia); `buildCodeAssets` is already false for web targets, so build hooks return early
- **Android app-process BrowserPort (U12)**: one androidx.webkit profile per session, assigned right after construction (`setProfile` throws after the first load or `evaluateJavascript`); Chromium refuses `deleteProfile` for seconds after `destroy()`, so closed profiles are emptied and pooled (`ProfilePool`), never reused unconfirmed. Messages use one `addWebMessageListener` bridge per session (engine-attested origin) and `addDocumentStartJavaScript` channel scripts that look the bridge up per call (loadData documents get it after document start); WebView reports a loadData document's URL as `about:blank`. Background = no started Activity for 700 ms. Replay mode (`AndroidBrowserConfig.offline`) routes the process's WebViews to a refusing loopback proxy; debug builds allow cleartext to 127.0.0.1 only (`android/app/src/debug/res/xml/srt_debug_network_security.xml`)
- **Paperback fixtures on Android**: the plugin's debug-only `paperbackFixtureAssets` Gradle task packages `fixtures/source_captures/paperback/` as assets under `source_captures/paperback/`; `copyFixtureAssetDirectory('source_captures/paperback')` copies them to the app cache; release variants carry none
